title: Local Mode
subtitle: Running the tool locally (mode: local)
description: Install the router-diagnostics plugin and chart, then collect a support bundle using your own kubectl access.
---

Use `mode: local` when you have kubectl access to production yourself. Collection runs on your own machine, using your own credentials.

## Step 1: Install the `router-diagnostics` Helm plugin

Install this once on the machine you'll collect from:

```bash
helm plugin install https://github.com/apollographql/router-diagnostics-helm-plugin
```

This gives you a single `helm router-diagnostics collect` command. It also does two things for you automatically:

- Installs a pinned version of [troubleshoot's `support-bundle` binary](https://troubleshoot.sh/docs/support-bundle/introduction), private to the plugin.
- Bridges your machine to the router's metrics port, if enabled — see [Collecting Metrics](../collecting-metrics#mode-local) for exactly what this does, the permission it needs, and the full list of prerequisites for metrics to be collected at all.

## Step 2: Install the Helm chart

**If you deployed the router with the official Apollo Helm chart:**

```bash
helm install router-diagnostics apollo/router-diagnostics \
  --namespace production \
  --set namespace=production \
  --set mode=local
```

`namespace` is the only value you need to supply, the chart's collectors target your router by its standard `app.kubernetes.io/name=router` label.

**If you're on a raw-manifest or custom deployment:**

```bash
helm install router-diagnostics apollo/router-diagnostics \
  --namespace production \
  --set namespace=production \
  --set selector="app=my-router" \
  --set configMapName=my-config \
  --set mode=local
```

Since none of the official chart's conventions apply to your deployment, supply your pod selector and ConfigMap name in addition to the namespace, so the chart's collectors know where to find your router and its configuration.
Optionally, supply `metricsPort` if your metrics are not exposed via the default `9090`.

## Step 3: Collect a support bundle

```bash
helm router-diagnostics collect --namespace production
```

Run it again any time you want another bundle.

## Cleaning up

Installing the chart leaves the spec ConfigMap plus Helm release metadata. If you'd rather leave nothing behind:

```bash
helm uninstall router-diagnostics --namespace production
```

If you expect to collect more than once, leaving the chart installed means subsequent runs are just `helm router-diagnostics collect --namespace production`, with no reinstall.
