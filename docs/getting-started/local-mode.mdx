---

Use `mode: local` when you have kubectl access to production yourself. Collection runs on your own machine, using your own credentials.

## Step 1: Download the `router-diagnostics` collect script

Download this once, onto the machine you'll collect from, and make it executable:

```bash
curl -sSLo collect.sh https://rover.apollo.dev/<path-TODO>/router-diagnostics-collect/latest
chmod +x collect.sh
```

This gives you a single `./collect.sh` command. It also does two things for you automatically:

- Caches a pinned version of [troubleshoot's `support-bundle` binary](https://troubleshoot.sh/docs/support-bundle/introduction) locally, keyed by version.
- Bridges your machine to the router's metrics port, if enabled — see [Collecting Metrics](../collecting-metrics#mode-local) for exactly what this does, the permission it needs, and the full list of prerequisites for metrics to be collected at all.

`collect.sh` takes `--namespace`/`--selector`/`--metrics-port` flags. Whatever you pass to `helm install` below, pass again here (`--metrics-port` maps to the chart's `metricsPort` value).

## Step 2: Install the Helm chart

**If you deployed the router with the official Apollo Helm chart:**

```bash
helm install router-diagnostics oci://registry-1.docker.io/apollograph/router-diagnostics-chart \
  --namespace production \
  --set namespace=production \
  --set mode=local
```

`namespace` is the only value you need to supply, the chart's collectors target your router by its standard `app.kubernetes.io/name=router` label.

**If you're on a raw-manifest or custom deployment:**

```bash
helm install router-diagnostics oci://registry-1.docker.io/apollograph/router-diagnostics-chart \
  --namespace production \
  --set namespace=production \
  --set selector="app=my-router" \
  --set configMapName=my-config \
  --set mode=local
```

Since none of the official chart's conventions apply to your deployment, supply your pod selector and ConfigMap name in addition to the namespace, so the chart's collectors know where to find your router and its configuration.
Optionally, supply `metricsPort` if your metrics are not exposed via the default `9090`.

## Step 3: Collect a support bundle

**Official Apollo Helm chart:**

```bash
./collect.sh --namespace production
```

**Raw-manifest or custom deployment** — pass the same `selector` (and `--metrics-port`, if you set a non-default `metricsPort`) you gave `helm install` above:

```bash
./collect.sh --namespace production --selector "app=my-router"
```

`--namespace` here must match the value you gave both `helm install --namespace` and `--set namespace=` in Step 2 — `collect.sh` uses it to find the spec ConfigMap the chart rendered there. See [local-mode-details](../local-mode-details) for why.

Run it again any time you want another bundle.

## Cleaning up

Installing the chart leaves the spec ConfigMap plus Helm release metadata. If you'd rather leave nothing behind:

```bash
helm uninstall router-diagnostics --namespace production
```

If you expect to collect more than once, leaving the chart installed means subsequent runs are just `./collect.sh --namespace production` again, with no reinstall.
